# Дообучение модели помощника (Qwen3.5-2B, Mac на Apple Silicon)

LoRA-дообучение Qwen3.5-2B под сервис: база знаний, права ролей, чтение контекста дня
и честное «не знаю» на вопросы вне справки. Обучение идёт на Mac с 16 ГБ памяти через
MLX; результат превращается в GGUF и загружается в Ollama вместо стандартной модели.

## Файлы

| Файл | Что делает |
| --- | --- |
| `kb_qa.yaml` | Пары «вопрос → ответ» по разделам базы знаний, для всех ролей |
| `build_dataset.py` | Собирает обучающий набор тем же кодом промптов, что сервис |
| `gated_delta_chunked.py` | Блочный расчёт линейного внимания Qwen3.5 для обучения |
| `train.py`, `lora_config.yaml` | Запуск `mlx_lm.lora` с этим расчётом и настройки обучения |
| `evaluate.py` | Сравнение базовой и дообученной модели на вопросах, которые идут в модель |
| `merge_lora.py` | Вливание LoRA в исходный чекпоинт Hugging Face |
| `check_gated_delta.py` | Проверка блочного расчёта против исходного цикла mlx-lm |

## Данные

`build_dataset.py` строит каждый пример через `build_messages` сервиса: те же правила
роли, та же «Справка» из поиска, тот же блок данных. Источники:

1. **База знаний** — `kb_qa.yaml`. Раздел-источник ответа гарантированно попадает
   в «Справку», как при работе сервиса.
2. **Вопросы о дне** — контексты «Моего дня» по форме синтетического набора
   `data/synthetic` (смены исполнителей, окна, статусы, порядок визитов); эталонные
   ответы строит `app/modules/chat/facts.py`, поэтому они точные.
3. **Вопросы вне базы** — эталон «Не знаю — уточните у …».

Вопросы, похожие на проверочные из `eval/questions.yaml` (включая отложенные `h-*`),
в набор не попадают.

## Почему нужен `gated_delta_chunked.py`

В режиме обучения mlx-lm считает слои линейного внимания Qwen3.5 циклом по токенам и
хранит состояние 128×128 на каждый токен для обратного прохода — на примере в 1 500
токенов это не помещается в 16 ГБ. Модуль считает то же самое блоками по 64 токена
(WY-форма, как в ядрах для GPU): совпадение с исходным расчётом до ~1e-7 по выходу и
~1e-6 по градиентам, прямой и обратный проход на 1 500 токенах — ~0,6 ГБ.

## Шаги

Окружение (Python 3.12, из папки с моделями и данными, например
`~/Downloads/beeline-business/finetune`):

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python mlx-lm pydantic-settings pyyaml snowballstemmer httpx
.venv/bin/hf download Qwen/Qwen3.5-2B --local-dir models/Qwen3.5-2B
.venv/bin/mlx_lm.convert --hf-path models/Qwen3.5-2B --mlx-path models/qwen35-2b-4bit -q --q-bits 4
```

Датасет (из папки `assistant`, окружением сервиса):

```bash
python -m finetune.build_dataset --synthetic ../data/synthetic/standard/dataset.zip --out ~/Downloads/beeline-business/finetune/data
```

Обучение (из папки `assistant/finetune`; модель во время обучения хранится в 4 битах —
QLoRA, ~3,5 ГБ памяти):

```bash
FT=~/Downloads/beeline-business/finetune
$FT/.venv/bin/python train.py -c lora_config.yaml --model $FT/models/qwen35-2b-4bit --data $FT/data --adapter-path $FT/adapters/v1
```

Проверка до и после (базовая модель в полной точности, адаптер поверх неё):

```bash
$FT/.venv/bin/python evaluate.py --model $FT/models/Qwen3.5-2B --out $FT/base.json
$FT/.venv/bin/python evaluate.py --model $FT/models/Qwen3.5-2B --adapter $FT/adapters/v1 --out $FT/tuned.json
```

Слияние и перенос в Ollama:

```bash
$FT/.venv/bin/python merge_lora.py --base $FT/models/Qwen3.5-2B --adapter $FT/adapters/v1 --out $FT/models/qwen35-2b-beeline
$FT/convert-venv/bin/python $FT/llama.cpp/convert_hf_to_gguf.py $FT/models/qwen35-2b-beeline --outtype q8_0 --outfile $FT/qwen35-2b-beeline-q8_0.gguf
```

Modelfile берётся у стандартной модели, чтобы шаблон чата и параметры совпадали:
`ollama show qwen3.5:2b --modelfile`, строку `FROM` заменить на путь к GGUF, затем
`ollama create qwen3.5-beeline:2b -f Modelfile` и в `.env` указать
`ASSISTANT_MODEL=qwen3.5-beeline:2b`.

## Результат первого дообучения (29.09.2026)

- Данные: 157 пар по базе знаний (262 примера с учётом ролей), 222 вопроса о дне
  на 60 синтетических днях, 60 вопросов вне базы; разбиение на обучение (485) и проверку
  (59) по вопросам, а не по примерам — иначе один вопрос для двух ролей попадал в обе части.
- Обучение: QLoRA, rank 8, 16 последних слоёв, 1000 шагов (~2 эпохи), скорость 1e-5 с
  косинусным спадом, ~65 минут на MacBook M1 Pro, пик памяти 3,7 ГБ. Ошибка на проверке:
  0,78 → 0,25 (200) → 0,21 (400–1000). Выбран шаг 800.
- Первая попытка со скоростью 5e-5 испортила ответы (обрывочные фразы, «Я назначаю
  исполнителей») при хорошей ошибке на проверке: с множителем LoRA 20 в mlx-lm это слишком
  много, стандарт — 1e-5.

Ручная разметка ответов модели (MLX, одинаковые промпты; «не знаю» — отказ, хотя ответ
был в справке):

| Набор | Модель | Верно | Частично | «Не знаю» | Неверно |
| --- | --- | --- | --- | --- | --- |
| 29 основных вопросов | Qwen3.5-2B | 16 | 4 | 4 | 5 |
| | дообученная | 23 | 2 | 1 | 3 |
| 16 отложенных вопросов | Qwen3.5-2B | 8 | 1 | 2 | 5 |
| | дообученная | 8 | 1 | 2 | 5 |

На вопросах по темам из обучения модель стала заметно точнее и короче (правильные
кнопки, права ролей, «не знаю» вне справки). На вопросах о темах, которых в обучающих
парах не было, итог тот же, что у базовой: три ответа лучше, три хуже. Чтобы улучшить и их,
нужно больше разнообразных пар на каждый раздел, а не больше шагов.

Слитая модель в GGUF Q8_0 — 2,1 ГБ; в Ollama создаётся как `qwen3.5-beeline:2b`.
