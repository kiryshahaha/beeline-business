# База знаний ассистента

Тексты описывают текущую систему: состояния заявок (`dispatched`, `en_route`,
`in_progress`, `completed`, `cancelled`), одного исполнителя на заявку, участки, план дня,
оборудование на день и четыре категории работ с нормативами из справочника видов работ.
Кнопки исполнителя («Выехал», «Начал работу», «Завершил» с подтверждением диспетчера,
«Задерживаюсь», «Сообщить о проблеме») соответствуют согласованным ручкам приложения
исполнителя. Когда интерфейс будет готов, названия кнопок нужно сверить с ним.

Вопросы о конкретной смене и заявках (время, порядок, статус, причины переносов)
ассистент берёт не отсюда, а из данных бэкенда — см. `app/modules/chat/facts.py`.

## Формат файла

```markdown
---
title: Короткое название документа
roles: [worker, foreman, observer]
category: connection
---

## Раздел
Текст раздела.
```

- `roles` — кому документ показывается ассистентом. Роли совпадают с бэкендом:
  `worker` — исполнитель, `foreman` — бригадир, `observer` — диспетчер.
- `category` — необязательно: `emergency`, `connection`, `repair` или `additional`,
  как `tickets.category`. Если открыта заявка этой категории, разделы документа
  поднимаются в поиске, а памятки других категорий опускаются.
- Каждый раздел `##` — отдельный фрагмент поиска. Держите раздел коротким
  (до ~150 слов) и самодостаточным: модель видит только найденные фрагменты.

`README.md` в поиск не попадает.
