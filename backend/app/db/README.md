# Хранение данных

| Файл | Назначение |
| --- | --- |
| `base.py` | Общая SQLAlchemy metadata, соглашения имён ограничений, Identity PK |
| `models.py` | Явный импорт всех моделей для Alembic и общего реестра |
| `session.py` | Ленивое создание engine и сессия на HTTP-запрос |

Описание полей расположено рядом с моделями в [предметных модулях](../modules/README.md).
Основные связи: город → улица/район → здание → подъезд/место; место → заявка/офис;
пользователь → worker → навыки/бригада/назначения/маршруты;
офис + оборудование → остаток; заявка + оборудование → выделенное количество.

`routes.geojson` — исторический JSONB снимок; ссылки внутри JSON дополнительно
проверяются сервисом, их нельзя считать обычными SQL-внешними ключами.
`data_imports` — служебные квитанции идемпотентного импорта, не предметный каталог.
`work_types` — справочник видов работ с нормативами; стартовые строки создаёт миграция 0011.

Изменяйте схему через [Alembic](../../migrations/README.md). Не используйте
`create_all` вместо миграций при запуске приложения. Интеграционные тесты проходят
upgrade/downgrade и `alembic check` в отдельных схемах.

Планирование добавляет три таблицы требований вида работ (0012) и две таблицы (0013):
planning_plans хранит UUID, дату, TTL, согласованный снимок входа, результат и состояние;
planning_plan_routes связывает применённый план с сохранёнными routes.
Связи и check-ограничения не позволяют создать применённый план без квитанции.
План не заменяет tickets/assignments: изменения в них выполняются атомарно при apply.
