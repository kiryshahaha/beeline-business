# Уведомления

`notification_events` — долговечная очередь/история событий с получателем, заявкой, JSON-данными, попытками и метками доставки. `push_subscriptions` — устройства/токены. Диспетчер обслуживает WebSocket и опциональный Firebase. В тестах реальная внешняя рассылка не нужна; Firebase выключен по умолчанию.

| Файл | Ответственность |
| --- | --- |
| `models.py` | Очередь событий и push-подписки |
| `enums.py` | Виды ticket_assigned, ticket_status_changed и worker-app событий |
| `schemas.py` | HTTP-контракты истории и регистрации токенов |
| `repository.py` | Выборка/обновление очереди и токенов |
| `service.py` | История пользователя, регистрация и удаление подписок |
| `dispatcher.py` | Фоновая доставка, повторы и обработка ошибок; работает только в процессе с ролью доставки |
| `connections.py` | Активные WebSocket-соединения процесса; одно событие на сокет — один раз |
| `topology.py` | Роль доставляющего процесса (advisory lock на отдельном соединении) |
| `firebase.py` | Граница SDK Firebase и отключённый шлюз |
| `router.py` | HTTP-история, push-токены и WebSocket |

## Поддерживаемый режим

Живые события доставляет один процесс backend. `websocket_delivered_at` ставится, только
если событие получил хотя бы один сокет; если получатель не был подключён —
`websocket_missed_at`, и событие приходит из истории. Клиент передаёт `last_event_id` в
сообщении `authenticate` и получает пропущенное (до 200 событий, дальше —
`replay_truncated` и `GET /api/v1/notifications?after_id=`). Процесс без роли доставки
закрывает новые сокеты с кодом 1013. Подробно — [Артефакты_нейронки/OPERATIONS.md](../../../../Артефакты_нейронки/OPERATIONS.md).

После первого успешного применения плана backend отправляет PostgreSQL `NOTIFY` в
транзакции плана. Процесс с ролью доставки слушает канал и рассылает активным сокетам
`{"type":"schedule_updated"}` после фиксации транзакции. Сигнал не хранится в
`notification_events` и не попадает в историю уведомлений; экран перечитывает
`GET /api/v1/schedule`. При повторном запросе уже применённого плана и при отказе
сигнал не отправляется.

Worker-app события сохраняются в ту же очередь и проходят ту же WebSocket/push доставку:
`ticket_unassigned`, `ticket_rescheduled`, `ticket_window_changed`, события запроса и
решения подтверждения завершения, `ticket_delay_reported` и `ticket_problem_reported`.
Допустимые типы ограничены миграцией; тесты используют отключённый dispatcher и не
отправляют реальные push-сообщения.

Общий API описан в [backend README](../../../README.md); ограничения существующей
системы — в [аудите](../../../../Артефакты_нейронки/AUDIT_2026-09-18.md). Миграции находятся
в [migrations](../../../migrations/README.md), проверки — в [tests](../../../tests/README.md).
