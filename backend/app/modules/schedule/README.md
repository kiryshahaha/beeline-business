# Расписание смен

Только чтение: собственных таблиц у модуля нет. `GET /api/v1/schedule?date=&office_id=` отдаёт
бригады и исполнителей со сменами и назначенными заявками на сутки, чтобы фронтенд
нарисовал таймлайн. Сутки считаются по Москве (+03:00), как в модуле маршрутов.

| Параметр | Смысл |
| --- | --- |
| `date` | `YYYY-MM-DD`, 2000–2100; по умолчанию сегодня по Москве |
| `office_id` | Необязательный фильтр офиса бригад; несуществующий офис — `404` |

Доступ: `observer` видит все бригады, `foreman` — только свою (фильтр офиса её не расширяет),
`worker` получает `403`, без токена — `401`.

Правила построения:

- Офис исполнителя определяется через бригаду: `brigade_members → brigades.office_id`.
  Исполнители без бригады приходят в `unassigned_workers` только наблюдателю без `office_id`.
- Смена хранится как время суток и повторяется каждый день; выходных и графиков в модели нет.
  В `shifts` попадают смены, пересекающие сутки, с полными датами начала и конца. Ночная смена
  22:00–06:00 даёт две записи: вчерашнюю до 06:00 и сегодняшнюю с 22:00. Обрезать их по краям
  суток (`day_start`, `day_end`) должен фронтенд.
- В `tickets` попадают назначенные исполнителю заявки любого статуса, у которых плановый
  интервал `planned_start_at`–`planned_end_at` пересекает сутки. Заявки без плана не выводятся.
- Бригады упорядочены по ID, исполнители — по фамилии и имени, заявки — по плановому началу.

## План дня исполнителя (`day_plan`)

`shifts` и `tickets` описывают календарные сутки. `day_plan` отвечает на другой вопрос —
что у исполнителя запланировано на эту дату — и строится в той же модели смены, что
использует планировщик (`planning.eligibility.prepare`): смена даты начинается в этот день,
ночная заканчивается утром следующего. Заявка относится к той смене, в 24-часовом окне
которой начинается её плановый визит: время между сменами делится пополам, поэтому
переработка в 19:30 после смены 9–18 — это сегодня, а визит в 02:00 — вчерашняя ночная
смена, а не сегодняшняя. Так один момент никогда не попадает в два дня.

| Поле | Откуда |
| --- | --- |
| `shift_start`, `shift_end` | Смена даты в модели планировщика |
| `availability` | `worker_day_states` на эту дату — те же строки, по которым планировщик исключает инженера |
| `route` | Последний сохранённый маршрут исполнителя на дату, его ревизия плана дня и признак `is_current_plan` |
| `visits` | Визиты из маршрута (`source=route`: прибытие, ожидание, работа); назначенная заявка без маршрута — по своему плановому времени (`source=ticket`) |
| `service_minutes`, `travel_minutes`, `waiting_minutes` | Работа, дорога между точками маршрута и ожидание открытия окна — раздельно |
| `free_minutes` | Смена минус работа, дорога и ожидание внутри неё; у недоступного исполнителя 0 |
| `overtime_minutes` | Время визитов за пределами смены. Политики переработки нет, это нарушение плана |
| `conflicts` | См. ниже |

Коды конфликтов: `route_outdated` — в маршруте есть заявка, больше не запланированная у
исполнителя на эту дату; `not_in_route` — назначенной на дату заявки нет в маршруте;
`route_time_mismatch` — плановое время заявки разошлось со временем в маршруте;
`visits_overlap` — визиты пересекаются; `outside_shift` — визит выходит за смену;
`during_absence` — визит приходится на отмеченную недоступность.

`unassigned_tickets` — открытые заявки без исполнителя, окно визита которых пересекает
сутки. Участок заявки — её собственный, иначе участок её здания; участок офиса —
`offices.service_area_id`, иначе участок здания офиса. С `office_id` и для бригадира видны
только участки видимых офисов, наблюдатель без фильтра видит все.

`plan_revisions` — текущая ревизия плана дня для каждого видимого участка (`null`, если
план на дату не применялся). Логика дня лежит в `timeline.py` и используется также
аналитикой загрузки, поэтому расписание и загрузка не расходятся.

| Файл | Ответственность |
| --- | --- |
| `schemas.py` | Ответ таймлайна: бригады, бригадир, исполнители, смены, заявки |
| `repository.py` | SQL бригад, участников, заявок за сутки, маршрутов, отметок недоступности и очереди без исполнителя |
| `timeline.py` | Смена планировщика, окно дня, дорога/ожидание/работа по маршруту и конфликты — без БД |
| `service.py` | Интервалы смен, план дня исполнителей (`load_worker_days`), сборка ответа и видимость |
| `router.py` | HTTP, проверка параметров и ролей |

Общий API описан в [backend README](../../../README.md), проверки — в [tests](../../../tests/README.md)
и в папке Bruno `17-schedule`.
