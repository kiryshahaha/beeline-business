# Оборудование и склад

`appliances` — номенклатура с типом, единицей и признаком активности. `appliance_stocks` хранит физический остаток по паре офис/позиция. `ticket_appliances` связывает заявку, позицию, офис и количество. Резерв офиса — количество открытых заявок (planned/in_progress), которое ещё лежит в офисе; доступно = остаток − резерв. TOOL не списывается как расходник при завершении.

## Оборудование как физический ресурс инженера (T08)

Единица оборудования находится в одном месте: склад офиса → руки инженера → клиент.
Каждое перемещение — строка журнала `appliance_movements` внутри операции
`appliance_operations` (issue, return, consume, restore) с ключом идемпотентности,
автором, инженером, заявкой и моментом записи. Остатки на руках — `worker_appliances`
(строка есть, пока количество положительное). Состояние позиции заявки —
`ticket_appliance_states`: нет строки — позиция зарезервирована в офисе; `holder_worker_id` —
выдана инженеру; `consumed_operation_id` — списана у клиента.

У инженера по каждой позиции: `on_hand` — на руках, `committed` — закреплено за
открытыми заявками, `free` — свободный запас (резерв комплекта и то, что освободилось).

| Операция | Что происходит |
| --- | --- |
| Комплект на день | `GET /workers/{id}/equipment?date=` считает позиции назначенных заявок дня, ещё лежащие в офисе, и доводит свободный запас до нормы офиса. `shortages` заранее показывает нехватку на складе. |
| Выдача | `POST /workers/{id}/equipment/issue` фиксирует этот комплект до выезда: склад уменьшается, у инженера прибавляется, позиции заявок переходят на руки. Повторный вызов в течение дня — отдельное событие пополнения. |
| Списание | При завершении заявки каждая позиция списывается ровно один раз: с рук держателя или, если комплект не выдавался, со склада офиса (источник записан в журнале). Проверка остатка защищена: нехватка — `409 inventory_inconsistent`, без `GREATEST(0, …)`, статус заявки не меняется. |
| Переоткрытие | Повторно не списывает. Если устройство действительно вернулось от клиента, `POST /tickets/{id}/equipment/restore` с причиной возвращает его туда, откуда оно было списано. |
| Отмена | Резерв офиса освобождается сам. Выданное остаётся у инженера свободным запасом — на склад автоматически не «телепортируется». |
| Возврат | `POST /workers/{id}/equipment/return`: свободные единицы в офис бригады (или указанный), либо позиции конкретных заявок — в офис их резерва; такая позиция снова считается зарезервированной в офисе. |
| Переназначение | `PUT /tickets/{id}/assignees`: выданное оборудование не переходит к другому исполнителю само — нужен свободный запас нового исполнителя (тогда позиция закрепляется за ним) или сначала возврат (`409 equipment_held_by_worker`). Инженеру, у которого смена по заявке уже началась, заявку с оборудованием из офиса можно дать только при свободном запасе на руках (`409 equipment_not_on_hand`); иначе сначала выдача-пополнение. |

Норма резерва — `office_kit_reserves` (`GET|PUT /offices/{id}/kit-reserve/{appliance_id}`, 0
удаляет норму): столько единиц каждый инженер офиса берёт сверх назначенных заявок.
Вес и объём не моделируются: принято, что комплект дня и резерв инженер забирает целиком.
Передача между инженерами и точки встречи не реализованы; перемещение делается возвратом
и новой выдачей.

Все изменения берут общий advisory lock планирования, поэтому проверка остатка и
запись выполняются последовательно: две параллельные выдачи не выдают одну единицу
дважды. Одинаковый `operation_key` возвращает первую квитанцию (`already_applied=true`),
тот же ключ с другим запросом — `409 operation_key_conflict`.

Планировщик пока планирует только ещё не начавшиеся смены и опирается на резерв офиса;
выданные позиции в резерв офиса не входят. Перепланирование в течение дня (T06) должно
использовать `inventory.free_units`: офисный запас сам по себе не делает заявку выполнимой.

Миграция 0016 отмечает позиции заявок, завершённых до журнала, как уже списанные, чтобы
переоткрытие и повторное завершение не списали их второй раз. Новые таблицы не входят в
обмен CSV/XLSX (служебный журнал; перенос остатков на руках — задача T11).

| Файл | Ответственность |
| --- | --- |
| `models.py` | Номенклатура, остатки офисов, позиции заявок, остатки на руках, норма резерва, журнал и состояние позиций |
| `enums.py` | ApplianceType: девять типов, включая TOOL и CABLE |
| `schemas.py` | Создание/редактирование, остатки, позиции заявок, комплект, запросы операций, квитанции |
| `repository.py` | Запросы номенклатуры и склада, резерв офиса без выданных позиций |
| `service.py` | Доступ к заявке, проверка количества и свободного остатка, запрет правки выданного |
| `inventory.py` | Комплект, выдача, возврат, однократное списание, компенсация, правило переназначения, журнал |
| `router.py` | API номенклатуры, склада, позиций заявок, оборудования инженера и журнала |
