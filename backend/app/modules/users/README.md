# Пользователи и исполнители

`users` хранит имя, логин, хеш пароля и роль observer/foreman/worker. `workers`
расширяет пользователя сменой, `transport_type` и флагом `is_on_line`. `worker_skills` —
справочник навыков; `worker_skill_assignments` — связь многие-ко-многим.
`refresh_tokens` хранит хеши токенов и сроки/отзыв, не исходные токены.

| Файл | Ответственность |
| --- | --- |
| `models.py` | Пять таблиц пользователей, исполнителей, навыков и refresh-токенов |
| `enums.py` | UserRole и TransportType |
| `schemas.py` | Создание/изменение пользователя, профиль смены, примеры OpenAPI |
| `repository.py` | SQL, агрегация навыков и ограничения видимости бригад |
| `service.py` | Пароли, роли, профиль исполнителя, создание и изменение |
| `router.py` | Профиль /me, каталог пользователей, архив и восстановление, навыки и статус линии |

Тип транспорта: `car`, `walking`, `bicycle`, `public_transport`. Миграция 0009
заполняет старые профили значением walking. PATCH без transport_type сохраняет
прежнее значение; null и неизвестные значения отклоняются. При смене роли на worker
без явно указанного транспорта используется walking.

## Графики работы и исключения смен

Профиль исполнителя поддерживает графики работы:
- **`schedule_type`**: `"2/2"` или `"5/2"` (по умолчанию `"5/2"`, для Московского сценария `"2/2"` со сменой 10:00–22:00).
- **`cycle_start_date`**: опорная дата начала цикла для графика `2/2` (первый рабочий день 4-дневного цикла: 2 рабочих дня, 2 выходных).
- **`workdays_mask`**: битовая маска рабочих дней для `5/2` (по умолчанию `31` = Пн–Пт, биты 0–6: Пн=1, Вт=2, Ср=4, Чт=8, Пт=16, Сб=32, Вс=64).

### Исключения смен (`worker_shift_exceptions`)

Для ручной корректировки рабочего графика конкретного инженера на дату:
- `POST /api/v1/users/{id}/shift-exceptions`: создать исключение на дату (`route_date`, `is_day_off`, `shift_start`, `shift_end`, `comment`). Позволяет отметить рабочий день как выходной или выходной как рабочий с нестандартными часами смены.
- `GET /api/v1/users/{id}/shift-exceptions`: список исключений инженера с возможностью фильтрации по диапазону дат (`date_from`, `date_to`).
- `DELETE /api/v1/users/{id}/shift-exceptions/{exception_id}`: удаление исключения.
- `GET /api/v1/users/{id}/shift?route_date=YYYY-MM-DD`: расчётная смена инженера на указанную дату с учётом графика и действующих исключений (`is_working`, `start`, `end`, `is_exception`, `comment`).

## История и архив (T14)

Строка `workers` — историческая личность инженера: на неё ссылаются планы, маршруты,
назначения и события. Она не удаляется ни при смене роли, ни при архивировании.
Получать работу может только **активный исполнитель**: роль `worker` и
`users.archived_at IS NULL`. Это условие проверяют ручное назначение, состав бригады,
сохранение маршрута, планировщик (`worker_archived` / `invalid_worker_role`), статус линии,
недоступность, выдача оборудования, расписание и календарь.

- **Смена роли** worker → observer/foreman сохраняет профиль, навыки, маршруты и назначения;
  заканчиваются членство в бригаде и ссылка календаря.
- **`POST /api/v1/users/{id}/archive`** (observer) — вместо удаления: вход, refresh, access-токен,
  календарь и push-подписки прекращаются, членство в бригаде заканчивается, история читается
  как прежде. Повторный вызов возвращает ту же запись. Нельзя архивировать себя (`400`) и
  бригадира действующей бригады (`409`). `POST .../restore` возвращает запись, бригаду и
  календарь задают заново.
- Смена роли и архив требуют сначала передать активную работу: иначе `409
  worker_has_active_work` с `ticket_ids` (planned/in_progress) и `equipment_on_hand`.
- **`DELETE /api/v1/users/{id}`** удаляет только пользователя без истории. Иначе `409
  user_has_history` с `links` — число строк по таблицам. Список связей читается из
  внешних ключей каталога: новая таблица истории защищена автоматически, удаляются вместе
  с пользователем только сессии, токены, подписки, уведомления, навыки и членство.
- `GET /api/v1/users` скрывает архивные записи, `include_archived=true` показывает их;
  `archived_at` есть в каждом ответе.

Миграция 0023 добавляет `users.archived_at` и меняет внешние ключи `routes.worker_id` и
`ticket_assignments.worker_id` с CASCADE на RESTRICT: база сама не даст стереть историю.
Офисы и бригады через API не удаляются; бригаду и офис исторического плана показывает
его входной снимок (`workers` в `GET /api/v1/planning/plans/{id}`).

`PUT /api/v1/workers/{worker_id}/line-status` доступен наблюдателю. Значение `false`
освобождает будущие заявки `planned`; `in_progress` и завершённые заявки сохраняют
назначение. Значение `true` возвращает инженера в список доступных сотрудников без
автоматического восстановления заявок.
