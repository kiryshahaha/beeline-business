# Сохранённые маршруты

Модуль хранит уже построенные маршруты. Он не запускает оптимизатор, не назначает
исполнителей заявкам и не меняет расписание существующих заявок.

| Файл | Назначение |
| --- | --- |
| `models.py` | Таблица `routes`, JSONB-снимок, уникальность `(worker_id, route_date, route_number)` |
| `schemas.py` | Входные точки, LineString, структура FeatureCollection, порядок/время |
| `service.py` | Проверка мест и заявок, сборка GeoJSON, блокировки и видимость |
| `router.py` | POST, batch, список, чтение и скачивание GeoJSON |

`id` — технический ключ. `route_number` — номер построения маршрута конкретного
инженера на конкретный день: 1, 2, 3. Новая дата или другой инженер начинают
с 1. `sequence` — номер точки внутри маршрута, это третье отдельное понятие.
Сохранённые записи неизменяемы; перепланирование создаёт следующую запись.
Удаление работника каскадно удаляет его маршруты, как и прочие его рабочие связи.

Для сохранения нужен `observer`. Читать свои маршруты может работник,
маршруты текущих участников своей бригады — `foreman`, любые — `observer`.
Чужой маршрут скрывается ответом 404. Список поддерживает `worker_id`, `route_date`,
`limit` (1–100) и `offset`. Порядок: дата, инженер, номер.

Пример `POST /api/v1/routes`:

```json
{
  "worker_id": 9,
  "route_date": "2026-09-21",
  "stops": [
    {"location_id": 1, "arrival_at": "2026-09-21T09:00:00+03:00"},
    {"location_id": 2, "ticket_id": 20, "arrival_at": "2026-09-21T10:30:00+03:00"}
  ]
}
```

ID в примере нужно заменить существующими. Заявка обязана относиться к указанному
месту. У всех мест должны быть координаты. Точки идут в порядке посещения;
время с часовым поясом не убывает. Первая точка относится к `route_date` в московском
часовом поясе. Разрешён переход через полночь, длительность до 24 часов.
Повторение одной заявки в одном снимке запрещено; повторное посещение места допустимо.
Одна точка допустима и сохраняется без LineString.

Можно передать `geometry: {"type":"LineString","coordinates":[...]}` с настоящей
геометрией построенного пути. Её концы должны совпадать с первой/последней точкой.
Без geometry линия соединяет точки напрямую и помечается `source=straight_lines`;
она не является расчётом дороги или пробега. Переданная линия отмечается `provided`.
Координаты GeoJSON: **[долгота, широта]**, WGS84, как в
[RFC 7946](https://www.rfc-editor.org/rfc/rfc7946).

`POST /api/v1/routes/batch` принимает `{"routes":[...]}` до 100 маршрутов и сохраняет
их одной транзакцией. Ошибка в одном откатывает все. Блокировка строк работников
в порядке их ID защищает нумерацию от гонок и взаимных блокировок между пакетами.
Уникальный индекс служит дополнительной защитой на уровне БД.

`GET /api/v1/routes/{id}/geojson` возвращает самостоятельный файл
`application/geo+json`: общие свойства инженера/даты/номера и Point-features
с `location_id`, `ticket_id`, `sequence`, `arrival_at`; необязательный LineString.
Изменение координат справочника впоследствии не меняет исторический снимок.

Проверки из backend с `TEST_DATABASE_URL`:

```powershell
python -m unittest tests.test_exchange_and_routes_api tests.test_exchange_roundtrip_and_migration -v
```

Время посещения окна, доступность навыков, ограничения смены и транспортная матрица
остаются ответственностью построителя плана; сохранение не утверждает оптимальность.
