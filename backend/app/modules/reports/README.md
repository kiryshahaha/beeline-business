# Отчёты

Модуль формирует файлы для чтения человеком и не меняет состояние БД. Оба отчёта
доступны только роли `observer`.

## Выгрузка заявок

`GET /api/v1/reports/tickets/export` принимает фильтры `status`, `city_id`, `district_id`,
`brigade_id`. Параметр `format` выбирает `csv` или `xlsx`; по умолчанию — `xlsx`.
Строки упорядочены по ID заявки, без пагинации, с `Content-Disposition: attachment`
(`tickets.csv` / `tickets.xlsx`), `Content-Length`, `Cache-Control: no-store` и
`X-Content-Type-Options: nosniff`.

Одна выгрузка — не более 50 000 заявок. Сначала считается число совпавших строк; больше
лимита — `422 report_too_large` с `rows` и `max_rows`, файл не собирается. Строки читаются
серверным курсором пачками по 500 и пишутся во временный файл: до 8 МиБ в памяти, дальше
на диске. Ответ отдаётся потоком из этого файла, транзакция к этому моменту закрыта.
На лимите XLSX собирается примерно за 11 с, CSV — за 3 с; процесс занимает около 10 МиБ
сверх обычного вместо 250–370 МиБ при прежней загрузке всех строк в память.

## Отчёт по плану

`GET /api/v1/reports/plans/{plan_id}/export` — отдельный файл по одному preview или
применённому плану, не вариант выгрузки заявок. `format=xlsx` (по умолчанию) даёт листы,
`format=csv` — ZIP с одноимёнными CSV (`plan-{id}.xlsx` / `plan-{id}.zip`):

| Лист | Содержимое |
| --- | --- |
| `summary` | Состояние, результат, `is_current`, дата, ревизия, время расчёта/применения, политика и порядок целей, метрики, неназначенные по категориям, оценка доп. ресурса, предупреждения |
| `routes` | Инженер, номер маршрута после apply, транспорт, выезд/возврат, число визитов, расстояние, минуты пути/работы/ожидания |
| `visits` | Порядок визитов каждого инженера: заявка, название, вид работ, категория, приоритет, окно, прибытие, начало/конец работы, ожидание, факторы |
| `unassigned` | Неназначенные заявки: код, категория и текст причины, причины по каждому кандидату |
| `excluded_workers` | Исключённые инженеры и причина |

Поля заявок берутся из входного снимка плана, то есть такими, какими их видел расчёт;
ФИО инженеров — текущие. Времена — ISO с часовым поясом Москвы. Состояние и `is_current`
считаются в одном снимке REPEATABLE READ так же, как в `GET /api/v1/planning/plans/{id}`.
Неизвестный план — `404 plan_not_found`.

## Безопасная запись текста

Общее правило — `app/core/spreadsheet.py`, его же использует обмен данными:
текст, начинающийся с `=`, `+`, `-`, `@` (в том числе после пробелов, табуляций и
переводов строк) или с табуляции/перевода строки, таблица могла бы выполнить как формулу.

- **XLSX:** такой текст записывается строковой ячейкой (`t="inlineStr"`) без изменений и с
  `quotePrefix`, чтобы Excel не превратил его в формулу и после правки ячейки. Так же
  записываются значения вида `#N/A`, иначе openpyxl сохранил бы их как ошибку.
- **CSV:** перед таким текстом добавляется один видимый апостроф, остальной текст не меняется.
  В отличие от обратимого формата обмена здесь нет служебных `\N`, `\E`, `\T`.
- **Числа** (ID, приоритет, этаж, координаты, минуты) остаются числами: `-2` в числовом столбце
  не экранируется. Текстовые номера — подъезд, дом, квартира — экранируются как текст.
- XML не хранит управляющие символы `\x00–\x1f` (кроме табуляции и переводов строк) и
  `\ufffe`/`\uffff`: в XLSX они заменяются на `\ufffd`, в CSV остаются как есть.
- Ячейка XLSX вмещает 32 767 единиц UTF-16 (эмодзи — две). openpyxl молча обрезал бы
  длинный текст, поэтому такой файл не собирается: `422 xlsx_cell_too_long` с ID заявки
  (или листом плана), столбцом и длиной. CSV сохраняет значение полностью. Временные
  файлы openpyxl при отказе удаляются.

## Файлы

| Файл | Ответственность |
| --- | --- |
| `router.py` | Роли, query-параметры, потоковая отдача и заголовки файла |
| `service.py` | Столбцы и лимит выгрузки заявок, адрес одной строкой |
| `plans.py` | Листы отчёта по плану из сохранённого плана и его входного снимка |
| `repository.py` | Подсчёт и потоковое чтение заявок, ФИО инженеров |
| `tables.py` | Читаемые CSV/XLSX/ZIP-таблицы, типы ячеек, лимит XLSX, временный файл |
| `errors.py` | `ReportError`: HTTP-статус, `code`, русский `message` и связанные значения |

Проверки: `python -m unittest tests.test_report_tables` (без БД),
`python -m unittest tests.test_ticket_reports_api tests.test_plan_reports_api`
(PostgreSQL через `TEST_DATABASE_URL`), Bruno — папка `19-reports`.
