# Worker-facing API

Этот модуль собирает мобильный экран исполнителя из существующих сущностей users,
tickets, worker_day_states и day_plan_revisions. Участок определяется только общим
resolver-ом `service_areas.territory.resolve_worker`; смена берётся из users service,
который учитывает график 2/2 или 5/2 и исключения.

`GET /api/v1/me/day` доступен только worker. Он возвращает его заявки за московский
день, порядок и время прибытия из актуальной ревизии маршрута, текущий статус дня,
оборудование и историю снятых назначений. Активные `en_route` / `in_progress` заявки
показываются даже если начались накануне. Заявки и смены других исполнителей не
попадают в ответ.

Команды `POST /api/v1/tickets/{id}/start-route`, `/start`, `/delay` и `/complete`
используют общий execution service, атомарную ревизию заявки и `Idempotency-Key`.
Для worker авторство проверяется по текущему назначению, событие датируется временем
сервера, а тело не может подменить его `worker_id`. Выезд допустим из `assigned` и
`dispatched`. Завершение worker создаёт `pending` review; завершение диспетчером сразу
создаёт `confirmed` review.

`GET /api/v1/tickets/completion-reviews` доступен observer и foreman своей бригады.
`POST /api/v1/tickets/{id}/completion/confirm` и `/reject` доступны observer;
отказ и повторное открытие заявки выполняются в одной транзакции. `GET
/api/v1/tickets/{id}/changes` объединяет назначение, lifecycle-события, ревизии плана
и решения по завершению с проверкой видимости на роль.

`POST /api/v1/tickets/{id}/problem` добавляет комментарий, append-only work event и
уведомление диспетчерам атомарно, не меняя статус заявки. Изменения состояния требуют
ожидаемую ревизию и idempotency key.

`POST /api/v1/assistant/chat` проксирует короткий диалог на внутренний сервис
`http://assistant:8002/api/v1/chat`. Endpoint выключен, пока
`ASSISTANT_ENABLED=false`; `ASSISTANT_URL` валидируется и не может быть переопределён
внешним адресом. Для исполнителя запрос включает `day` на сегодня и `tomorrow_shift`.
При передаче `ticket_id` в контекст добавляется только доступная пользователю заявка;
исполнитель дополнительно получает последние 10 комментариев, оборудование и историю
изменений этой заявки. Для observer и foreman контекст заявки содержит только `TicketRead`.
История диалога ограничена десятью сообщениями, длина каждого текста — 2000 символов;
частота ограничена десятью запросами пользователя в минуту. Текст запроса и контекст
не пишутся в журнал. Если помощник выключен или недоступен, API возвращает 503.
