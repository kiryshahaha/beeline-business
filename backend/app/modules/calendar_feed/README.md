# Календарь исполнителя (.ics)

Исполнитель подписывается на свои заявки в Google Calendar, Apple Calendar или любом
клиенте iCalendar. Календари не умеют передавать `Authorization: Bearer`, поэтому файл
открывается по секретной ссылке с токеном. Относитесь к ссылке как к паролю.

| Метод | Путь | Доступ | Результат |
| --- | --- | --- | --- |
| POST | `/api/v1/schedule/calendar/token` | `worker` | Новая ссылка `{url, created_at}`; прежняя перестаёт работать |
| GET | `/api/v1/schedule/calendar/token` | `worker` | `{active, created_at}` — выпущена ли ссылка |
| DELETE | `/api/v1/schedule/calendar/token` | `worker` | `204`; календари перестают получать обновления |
| GET | `/api/v1/schedule/calendar.ics?token=…` | по токену | Файл `text/calendar`; неизвестный или отозванный токен — `404` |

Другие роли получают `403`: заявки назначаются только исполнителям.

## Токен

Таблица `calendar_tokens`: одна ссылка на пользователя, `user_id` — первичный ключ.
Хранится только SHA-256 токена, как у refresh-токенов, поэтому показать ту же ссылку
повторно нельзя — можно выпустить новую. Удаление пользователя удаляет и ссылку.
Таблица не входит в обмен CSV/XLSX.

Токен передаётся в строке запроса, поэтому попадает в журнал доступа сервера и прокси.
Храните такие журналы как конфиденциальные.

## Содержимое файла

- В файл попадают заявки исполнителя с плановым временем, закончившиеся не раньше
  30 дней назад и начинающиеся не позже чем через 60 дней. Заявки без плана не выводятся.
- Не больше 1000 событий. Если их больше, сначала берутся будущие визиты, начиная с
  ближайшего, и только оставшееся место отдаётся прошлым, начиная с последних. Ближайшее
  будущее не теряется из-за плотной истории, а календарь получает `X-WR-CALDESC` с
  пометкой, что показаны не все визиты.
- Заявка, снятая с исполнителя или переданная другому за последние 14 дней, публикуется
  ему ещё раз со `STATUS:CANCELLED` и тем же `UID`, но без адреса и описания: клиент,
  который хранит событие после его исчезновения из файла, отметит его отменённым.
  Источник — таблица `ticket_assignment_events`.
- `UID` постоянный (`ticket-<id>@beeline-business`): календарь обновляет событие, а не дублирует.
- `DTSTART`/`DTEND` — `planned_start_at`/`planned_end_at` в UTC; клиент показывает местное время.
- `SUMMARY` — «Заявка #42: название».
- `LOCATION` — город, улица и дом: навигаторы не понимают подъезд и квартиру.
  `GEO` — координаты места, если они есть.
- `DESCRIPTION` — тип работ, статус, полный адрес с подъездом, этажом и квартирой,
  окно визита по Москве, описание заявки и ссылка на карточку.
- `URL` и ссылка в описании — `FRONTEND_URL/tickets/<id>`, только если задан `FRONTEND_URL`.
- Заявка `wont_fix` получает `STATUS:CANCELLED`, остальные — `CONFIRMED`.
- Завершённая заявка остаётся в календаре как история, `SUMMARY` начинается с «✓».
- Файл просит клиентов обновляться раз в 15 минут (`REFRESH-INTERVAL`, `X-PUBLISHED-TTL`);
  Google Calendar обновляет подписки реже и по своему расписанию.

Календарь — дополнительный канал только для чтения, а не источник правды: изменение
доходит до клиента только при его следующем обновлении подписки, мгновенной доставки нет.
Как конкретный клиент (Google, Apple, Outlook) обрабатывает событие, исчезнувшее из файла
или ставшее `CANCELLED`, автоматическими тестами не проверяется — это нужно смотреть на
живом клиенте. Архивирование или смена роли закрывают ссылку сразу: владелец файла должен
быть активным исполнителем.

## Настройки

| Переменная | Смысл |
| --- | --- |
| `PUBLIC_API_URL` | Публичный адрес API для ссылки; пусто — адрес из запроса |
| `FRONTEND_URL` | Адрес фронтенда для ссылки на карточку заявки; пусто — ссылки нет |

| Файл | Ответственность |
| --- | --- |
| `models.py` | CalendarToken: хеш токена на пользователя |
| `repository.py` | Сохранение/отзыв токена, выборка заявок с адресом (ближайшие первыми) и снятых заявок |
| `ics.py` | Сборка iCalendar без обращения к БД |
| `service.py` | Выпуск токена, статус, отзыв, окно истории и горизонт |
| `router.py` | HTTP, роли и заголовки ответа |

Проверки — [tests](../../../tests/README.md) и папка Bruno `20-calendar`.
