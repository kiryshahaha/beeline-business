# Bruno: проверки API

Коллекция запускается **последовательно и целиком** на новой тестовой БД после
миграций и `seed_demo.py`. Первые папки проверяют существующие сценарии и сохраняют
токены/ID для последующих. Фиксированные имена и ожидания рассчитаны на один прогон
с чистого состояния; повторный запуск всей коллекции требует новой тестовой схемы/БД.

| Папки | Сценарии |
| --- | --- |
| 01–04 | Health, фильтры и пагинация заявок, создание, ошибки |
| 05–08 | Авторизация, назначения, статусы, комментарии, уведомления |
| 09–11 | Офисы, бригады, оборудование и склад |
| 12-worker-transport | Четыре вида транспорта, сохранение профиля, ошибки и доступ |
| 12-analytics | Сводка заявок и загруженность бригад, области observer/foreman, запрет worker и ошибки авторизации |
| 13-routes | Номер по инженеру/дню, история, GeoJSON, скрытие чужого маршрута, валидация |
| 14-data-exchange | 21 таблица, обе выгрузки, dry run, XLSX-импорт, повтор через CSV, ошибки и роли |
| 15-work-types | Справочник видов работ: сумма норматива, чтение по ID, создание и изменение наблюдателем, `403`, `404`, `409`, `401` |
| fixtures | Небольшой полностью вымышленный пакет: 24 заявки, 4 работника; ошибочный CSV |

Из backend в отдельной тестовой БД:

```powershell
python -m alembic upgrade head
python seed_demo.py
python -m uvicorn app.main:app --port 8000
```

В другом терминале из `backend/bruno`:

```powershell
npx --yes @usebruno/cli@4.1.0 run -r --env Local --reporter-junit ../bruno-results.xml
```

Для другого порта добавьте `--env-var base_url=http://127.0.0.1:18000`.
`environments/Local.bru` и `collection.bru` содержат только опубликованные
демонстрационные учётные данные. Не заменяйте их реальными паролями.

Файлы загрузки задаются относительно корня коллекции: `@file(fixtures/dataset.zip)`.
У запроса Bruno режим `body: multipartForm`, а блок данных — `body:multipart-form`.
Обновление fixtures, из backend:

```powershell
python generate_synthetic.py --output bruno/fixtures --seed 906 --tickets 24 --workers 4 --days 1
```

CI поднимает PostgreSQL, выполняет миграции/seed, ждёт `/health`, запускает всю
коллекцию и сохраняет JUnit. Падение assertions/tests возвращает ненулевой код.
