# Планировщик OR-Tools

Один stateless-сервис и один внутренний endpoint: `POST /api/v1/solve`.
Backend передаёт матрицы времени/расстояния по видам транспорта, индивидуальные смены,
окна начала работ, продолжительность обслуживания и допустимых исполнителей.
Здесь нет БД, Geoapify, сохранения назначений или второго варианта API.

## Запуск

Из папки planner, Python 3.12:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:PLANNER_SERVICE_TOKEN = "ваш-случайный-внутренний-токен"
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Тот же token задаётся backend. Запрос требует X-Planner-Token. Без настройки — 503,
при неправильном token — 401. Не публикуйте порт решателя напрямую в интернет.
`GET /health` — проверка работающего процесса.

## Устройство

- app/modules/solver/schemas.py — строгий контракт, совпадающий с backend solver_contract.py.
- app/modules/solver/service.py — OR-Tools VRPTW, матрица каждого транспорта, ограничения
  смен, обслуживания и навыков; статус поиска, конкретные времена и проверяемые метрики.
- app/modules/solver/router.py — авторизация и максимум два расчёта на процесс.
- app/body_limit.py — ограничение тела запроса 4 MiB до разбора JSON.
- tests — настоящий solver, API и сравнение небольших задач с полным перебором.

Задачи обязательны к явному описанию в allowed_vehicles; пустой список запрещает
назначение. Недостижимая дуга задаётся null одновременно во времени и расстоянии.
Все времена — целые минуты относительно начала дня, расстояния — целые метры.
Ночные смены могут выходить за 1440 минут. Сервис проверяет границы V≤20, N≤70, H≤2880.

Стоимость пути учитывает только время поездок. Время обслуживания входит в ограничение
смены, а не в стоимость. Backend задаёт одинаковый штраф пропуска V×H+1, что ставит
количество выполненных заявок выше экономии поездок. fixed_cost всегда 0.
FEASIBLE означает найденное допустимое решение с ограничением времени поиска;
OPTIMAL возвращается только для соответствующего статуса OR-Tools.

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python -m ruff check .
.venv\Scripts\python -m ruff format --check .
.venv\Scripts\python tests/generate_strong.py
```

OR-Tools закреплён на 9.15.6755. Установка и импорт нативной библиотеки обязательны:
при её отсутствии проверки завершаются ошибкой.
