# Микросервис планирования (Solver Service)

Сервис разрабатывается на FastAPI. Является полностью stateless-калькулятором (не ходит в БД и не делает внешних запросов), который решает классическую задачу маршрутизации — **Vehicle Routing Problem with Time Windows (VRPTW)**. 

Его главная цель — получать на вход готовые матрицы времени (которые собирает основной бэкенд) и возвращать математически оптимальные маршруты для инженеров с учетом их смен, квалификаций и времени на дорогу.

## Текущий этап

Микросервис полностью реализован, протестирован и готов к интеграции с основным бэкендом.

Доступные операции HTTP API:

- **Математическое ядро:**
  - `POST /api/v1/solve` — основной эндпоинт. Принимает матрицы времени (`time_matrix`) и расстояния (`distance_matrix`), временные окна (`time_windows`), квалификации (`allowed_vehicles`), штрафы (`penalties`), а также конфигурацию алгоритма (`search_time_limit_s`, `vehicle_fixed_cost` и др.). Возвращает оптимальные маршруты (`routes` с вычисленной `distance`), общий пробег (`total_distance`) и список отброшенных задач (`dropped_nodes`).
- **Система:**
  - `GET /health` — проверка работоспособности сервиса (liveness check).

## Технологии и структура

Python 3.12+, FastAPI, Google OR-Tools, Pydantic.

```text
planner/
├── app/
│   ├── main.py                # приложение FastAPI, регистрация роутеров, /health и OpenAPI
│   └── modules/
│       └── solver/
│           ├── router.py      # HTTP-эндпоинт POST /api/v1/solve
│           ├── schemas.py     # Pydantic-схемы валидации графа (SolveRequest, SolveResponse)
│           └── service.py     # инкапсуляция математики OR-Tools (RoutingModel)
├── test_solve.py              # тестовый скрипт для локальной проверки солвера
├── generate_strong.py         # скрипт для генерации сложных мок-данных
├── requirements.txt           # Python-зависимости (fastapi, ortools, pydantic)
├── .gitignore                 # исключает виртуальное окружение, кэш и временные файлы
└── README.md                  # документация сервиса (вы здесь)
```

Ответственность разделена аналогично основному бэкенду:
- `schemas.py` — строгая типизация и валидация входящих массивов графа;
- `router.py` — обработчик HTTP-протокола;
- `service.py` — изоляция сложной математической логики библиотеки `ortools`.

## Как запустить

Вам потребуется установленный Python 3.12+.

1. Перейдите в директорию микросервиса:
```powershell
cd planner
```

2. Создайте виртуальное окружение:
```powershell
python -m venv .venv
```

3. Установите зависимости:
```powershell
.\.venv\Scripts\python -m pip install -r requirements.txt
```

4. Запустите сервис на порту **8001** (чтобы он не конфликтовал с основным бэкендом, который работает на `8000`):
```powershell
.\.venv\Scripts\uvicorn app.main:app --reload --port 8001
```

Сервис будет доступен по адресу `http://127.0.0.1:8001`. 
Интерактивная документация Swagger (где можно потестировать API) — по адресу **`http://127.0.0.1:8001/docs`**.

## Особенности реализации OR-Tools

В классе `VRPTWSolver` (`app/modules/solver/service.py`) реализованы следующие механизмы:

- **Стратегия поиска:** Используется `PATH_CHEAPEST_ARC` для начального решения и метаэвристика `GUIDED_LOCAL_SEARCH` для нахождения глобального оптимума. Лимит поиска конфигурируется через `search_time_limit_s` (по умолчанию 3 сек).
- **Ограничения времени:** Смены инженеров ограничиваются через `time_windows` их стартовых узлов. Максимальное время ожидания (slack) конфигурируется через `slack_max` (по умолчанию 120 минут).
- **Минимизация персонала:** Алгоритм автоматически стремится минимизировать число используемых инженеров за счет штрафа за вывод машины на смену, который задается параметром `vehicle_fixed_cost`.
- **Допуск исполнителей (Skills):** Фильтрация навыков (`allowed_vehicles`) реализована через вызов `RemoveValue(v)` из домена переменной `VehicleVar`.
- **Сброс задач:** Любая задача может быть отброшена алгоритмом (`AddDisjunction`), если штраф за её сброс меньше суммарных затрат на выполнение.
