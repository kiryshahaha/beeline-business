# Синтетические данные планирования

Все имена, адреса и точки вымышлены. Шесть наборов в CSV ZIP и XLSX:

| Набор | Заявки / инженеры | Сценарий |
|---|---|---|
| mixed | 24 / 4 | Все четыре транспорта, явные навыки и резервы оборудования |
| duplicate_coordinates | 24 / 4 | Разные заявки по одним координатам |
| night | 24 / 4 | Смена 22:00–06:00, окончание на следующий день |
| rejections | 24 / 4 | Завершённая заявка, неизвестная работа, отсутствие резерва, короткое окно |
| overload | 50 / 4 | Суммарная длительность превышает возможности смен |
| volume | 50 / 20 | Максимальный размер одного запроса |

Дата 2030-01-15, seed=1900. До этой даты набор пригоден для ручного preview;
автоматические тесты фиксируют часы на 2030-01-14. В manifest.json — SHA-256
файлов и число строк каждой таблицы. Генератор проверяет все строки штатным
парсером и сравнивает содержимое CSV/XLSX. Импорт применять в отдельной тестовой БД.

Генерация из backend:
`python generate_planning_synthetic.py --output ../data/planning`.
Большие наборы обмена на 1500 и 10000 заявок находятся в ../synthetic;
они содержат историю и отрицательные сценарии и не являются одним допустимым планом дня.

`policy_objective_cases.json` содержит 11 сравнений метрик для контракта T01:
приоритет аварии, цена ASAP, подключение против ремонта, покрытие, число инженеров,
дорога, стабильность и полное равенство. Это reference-проверки правил сравнения,
а не заявки для импорта и не результат работы native solver. Каждый пример содержит
ожидаемый выбор и объяснение; целевая иерархия ещё не включена в OR-Tools.

`python verify_synthetic.py` из backend проверяет все сохранённые CSV/XLSX,
контрольные суммы, количества строк, Bruno planning fixture и эти сравнения.
Генерация planning-пакетов не перезаписывает файл сравнений политики.
