# Синтетические наборы

Наборы описывают работу трёх участков кейса — «Восток», «Юго-восток» и «Югоцентр» —
на реальных адресах Москвы. Каждый дом — объект OpenStreetMap: улица, номер, корпус или
строение, координаты подъезда, этажность и нумерация квартир настоящие (© участники
OpenStreetMap, ODbL 1.0, см. [справочник](../../backend/synthetic_moscow/README.md)).
Квартира, этаж и подъезд заявки выбраны внутри реальных границ дома. Сами заявки, клиенты,
исполнители и комментарии вымышлены; дома из дневных файлов организатора исключены.

| Набор | Заявки | Исполнители | Дней | Форматы |
| --- | ---: | ---: | ---: | --- |
| [standard](standard/manifest.json) | 1 500 | 120 | 7 | dataset.zip (CSV), dataset.xlsx |
| [acceptance](acceptance/README.md) | 48 | 13, из них 12 в дневном составе | 1 | dataset.zip (CSV), dataset.xlsx |
| [large](large/manifest.json) | 10 000 | 240 | 14 | dataset.zip (CSV), dataset.xlsx |
| [Bruno fixtures](../../backend/bruno/fixtures/manifest.json) | 24 | 4 | 1 | оба формата |

## Что внутри

- **Участки и офисы** — как у организаторов: офисы на ул. Юных Ленинцев, 83 с4,
  Бирюлёвской ул., 1 с1 и Симферопольском проезде, 7. Район города в адресе системы —
  это участок; реальные районы Москвы участка перечислены в его описании.
- **Бригады** названы по бригадиру («Бригада Кузнецов»), по две на участок; каждая
  обслуживает свои соседние районы, заявка относится к бригаде своего района.
- **Исполнители** — старшие инженеры с тремя навыками кейса, монтажники подключений,
  техники по ремонту и линейные инженеры аварийной службы; дополнительные компетенции
  (сварка ВОЛС, IPTV и видеонаблюдение, допуск по электробезопасности). Смены 2/2
  10:00–22:00 и 09:00–21:00, 5/2 09:00–18:00 и 14:00–22:00, ночное дежурство
  22:00–10:00. Транспорт: служебный автомобиль, общественный транспорт, пешком, велосипед.
- **Виды работ** — четыре норматива организаторов (Подключение 90, Авария на ТКД 100,
  Дозаказ 40, Локальная заявка 50 минут, из них 20 — дорога) с правилом длительности
  `work_norm`, навыком кейса и обязательным роутером для подключения.
- **Заявки** в долях экспертов: 40% локальных, 40% подключений, 10% аварий, 10% дозаказов.
  Типы HelpDesk и окна по два часа (10–12 … 20–22) — как в дневных файлах; авария —
  на ТКД дома (подъезд без квартиры), окно 00:01–23:59, срок реакции 1–2 часа.
- **Оборудование** — номенклатура роутеров, ONT, приставок, кабеля, оптики, коммутаторов
  ТКД и инструмента; остатки офисов покрывают резервы заявок; норма запаса на руках инженера — коннекторы и патч-корды.

Последний день периода — день планирования: его заявки ждут назначения. Предыдущие дни —
история: выполненные визиты с фактическим исполнителем и временем и отменённые
с причиной. В наборах `standard` и `large` более 95% полных адресов (дом, подъезд,
этаж и квартира) уникальны; повторный визит в тот же дом остаётся возможным, но не
размножается на одной квартире. **Маршрутов, ревизий дня и журналов исполнения в наборах
нет** — их создают планировщик и приложение исполнителя. `python verify_synthetic.py`
проверяет адресное разнообразие, распределение статусов по дням, отсутствие сохранённых
маршрутов и соответствие CSV/XLSX.

Случаи дня перечислены в `manifest.json` (`scenarios`): соседи в одном доме с одинаковым
окном, аварии на весь день и ночью, дом без координат (новостройка, которую не знает
геокодер), подключение без свободного роутера в офисе.

Генерация, из backend:

```powershell
python generate_synthetic.py --output ../data/synthetic/standard
python generate_synthetic.py --output ../data/synthetic/large --seed 84 --tickets 10000 --workers 240 --days 14
```

Параметры по умолчанию: seed=42, дата 2026-09-21, 1 500 заявок, 120 исполнителей,
7 дней. `--date YYYY-MM-DD` меняет начальную дату. Одинаковые параметры дают одинаковые
предметные данные; CSV ZIP побайтово воспроизводим, XLSX может отличаться служебными
ZIP/Office-временами. Каждый созданный файл перечитывается штатным парсером.

## Загрузка и повторный запуск

Через API диспетчера загрузите dataset.zip или dataset.xlsx по
[контракту обмена](../../Артефакты_нейронки/DATA_EXCHANGE.md). Город, улицы, дома, квартиры,
навыки, оборудование и офисы, которые уже есть в базе (например, после `seed_demo.py`),
используются повторно; люди, бригады и заявки добавляются. Пользователи из обычного
импорта не получают общего известного пароля.

Для отдельной тестовой схемы:

```powershell
$env:TEST_DATABASE_URL='postgresql+psycopg://beeline_test:beeline_test@127.0.0.1:5432/beeline_test'
python seed_synthetic.py --seed 42
python seed_synthetic.py --seed 42
```

Будет создана схема `synthetic_42`; повторная команда вернёт `duplicate=true`.
Диспетчер — первый пользователь набора (логин печатается в ответе), тестовый пароль:
`SyntheticOnly123!`. Его можно переопределить переменной `SYNTHETIC_TEST_PASSWORD`.
Этот пароль устанавливается исключительно внутри `*_test` / `synthetic_<seed>`.

Чтобы открыть именно эту схему через API, задайте DATABASE_URL с параметром
`?options=-csearch_path%3Dsynthetic_42`, например:

```powershell
$env:DATABASE_URL='postgresql+psycopg://beeline_test:beeline_test@127.0.0.1:5432/beeline_test?options=-csearch_path%3Dsynthetic_42'
$env:NOTIFICATION_DISPATCHER_ENABLED='false'
python -m uvicorn app.main:app --port 8000
```

Для очистки и пересоздания только принадлежащего генератору набора:
`python seed_synthetic.py --seed 42 --reset`.
Не используйте эту схему для своих ручных данных: reset удаляет её целиком.
Изменение параметров существующего seed без reset намеренно не перезаписывает
старые данные и может завершиться конфликтом уникальности.
