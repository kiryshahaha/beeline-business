# Синтетические наборы

Все имена людей, названия адресов, оборудование, заявки и комментарии вымышлены.
Координаты — искусственные точки для тестов, не результат геокодирования адресов.
Каждый набор содержит все 25 предметных таблицу и связи между ними.

| Набор | Заявки | Исполнители | Дней | Снимки маршрутов | Форматы |
| --- | ---: | ---: | ---: | ---: | --- |
| [standard](standard/manifest.json) | 1 500 | 120 | 7 | 896 | dataset.zip (CSV), dataset.xlsx |
| [large](large/manifest.json) | 10 000 | 240 | 14 | 3 472 | dataset.zip (CSV), dataset.xlsx |
| [Bruno fixtures](../../backend/bruno/fixtures/manifest.json) | 24 | 4 | 1 | 8 | оба формата |

Кроме исполнителей есть наблюдатели и бригадиры, 3 города, 12 районов/улиц, 6 офисов,
бригады, 3 навыка, 27 позиций оборудования, складские остатки, назначения,
комментарии и история уведомлений. `manifest.json` содержит точные количества,
параметры генератора, размеры и SHA-256 файлов.

Сценарии отмечены в названиях/описаниях заявок: обычная нагрузка, пересекающиеся
окна, отсутствующий навык, неназначенные заявки, отсутствующие координаты,
нулевой остаток оборудования, пример срочной заявки и ночная смена.
Есть все четыре транспорта, все статусы заявок, комбинации 1–3 навыков,
повторные построения одного инженера за день, многодневная история,
многострочный текст и nullable-поля. Часть мест без координат распределена по набору.

Это данные для импорта и проверки сценариев, а не готовые оптимальные планы.
Маршруты представлены как сохранённые примеры посещения двух тестовых точек.
`urgent_example` — отметка сценария: поля приоритета пока нет в модели.
Складская нехватка представлена нулевым остатком позиции 26, а невозможный резерв
проверяется отрицательным тестом. Нет скрытых утверждений о поддержке этих
ограничений текущим end-to-end продуктом.

Генерация, из backend:

```powershell
python generate_synthetic.py --output ../data/synthetic/standard
python generate_synthetic.py --output ../data/synthetic/large --seed 84 --tickets 10000 --workers 240 --days 14
```

Параметры по умолчанию: seed=42, дата 2026-09-21, 1 500 заявок, 120 исполнителей,
7 дней. `--date YYYY-MM-DD` меняет начальную дату. Одинаковые параметры дают одинаковые
предметные данные; CSV ZIP побайтово воспроизводим, XLSX может отличаться служебными
ZIP/Office-временами. Каждый созданный файл перечитывается штатным парсером.

## Загрузка и повторный запуск

Через API диспетчера загрузите dataset.zip или dataset.xlsx по
[контракту обмена](../../docs/DATA_EXCHANGE.md). Пользователи из обычного импорта
не получают общего известного пароля.

Для отдельной тестовой схемы:

```powershell
$env:TEST_DATABASE_URL='postgresql+psycopg://beeline_test:beeline_test@127.0.0.1:5432/beeline_test'
python seed_synthetic.py --seed 42
python seed_synthetic.py --seed 42
```

Будет создана схема `synthetic_42`; повторная команда вернёт `duplicate=true`.
Диспетчер: `synthetic_42_observer_1`, тестовый пароль: `SyntheticOnly123!`.
Его можно переопределить переменной `SYNTHETIC_TEST_PASSWORD`. Этот пароль
устанавливается исключительно внутри `*_test` / `synthetic_<seed>`.

Чтобы открыть именно эту схему через API, задайте DATABASE_URL с параметром
`?options=-csearch_path%3Dsynthetic_42`, например:

```powershell
$env:DATABASE_URL='postgresql+psycopg://beeline_test:beeline_test@127.0.0.1:5432/beeline_test?options=-csearch_path%3Dsynthetic_42'
$env:NOTIFICATION_DISPATCHER_ENABLED='false'
python -m uvicorn app.main:app --port 8000
```

Для очистки и пересоздания только принадлежащего генератору набора:
`python seed_synthetic.py --seed 42 --reset`.
Не используйте эту схему для своих ручных данных: reset удаляет её целиком.
Изменение параметров существующего seed без reset намеренно не перезаписывает
старые данные и может завершиться конфликтом уникальности.
