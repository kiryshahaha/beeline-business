# Синтетический набор для плана 5

Генератор: `backend/generate_acceptance_dataset.py`. Начальное значение генератора — `5025`, дата маршрута — `2030-01-15`, часовой пояс — `Europe/Moscow`. Имена работников, улицы, номера домов и заявки вымышлены; координаты заданы вручную для проверки логики маршрутов.

`dataset.zip` и `dataset.xlsx` содержат одинаковые записи для штатного импорта. В них три участка, по четыре работника в дневном составе каждого участка, ещё один работник вне состава, 36 исходных заявок и 12 заявок, поступающих в течение дня. Среди новых заявок шесть аварийных и шесть обычных. В каждом участке есть адреса Москвы и удалённого города; московские адреса разных участков расположены рядом, чтобы расстояние не скрывало запрет на межучастковое назначение. Начальные ревизии содержат маршруты и состав работников на день.

`scenarios.json` перечисляет заявки, исходные назначения, события, работника вне дневного состава и отдельные пары для территориальной проверки. Заявка 37 находится в Москве рядом с адресом другого участка; заявка 38 проверяет маршрут в удалённый город своего участка. Аварийная заявка 43 имеет окно 10:00–12:00 при поступлении в 11:40, а заявка 45 — исходное окно 12:00–14:00. `negative_tickets.csv` хранит пустой, неизвестный и конфликтный признак HelpDesk; тест вызывает для этих строк серверный классификатор. `road_matrix.json` задаёт направленные времена, расстояния и два временных профиля. Источник матрицы — `deterministic_stub`: это искусственные дорожные данные. Матрица сама по себе не подтверждает работу Geoapify или оптимальность решения планировщика.

`manifest.json` фиксирует версии формата и генератора, количество записей, исходные назначения, размер и SHA-256 каждого файла. Общая команда проверки сверяет архивы через штатный парсер и проверяет контрольные суммы дополнительных файлов:

```sh
cd backend
python verify_synthetic.py
```

Для повторной генерации:

```sh
cd backend
python generate_acceptance_dataset.py --output ../data/synthetic/acceptance
```

Тест `tests.test_acceptance_dataset` проверяет состав, связность адресов и участков, эквивалентность CSV/XLSX, повторный импорт в PostgreSQL и классификацию отрицательных строк. Сценарии S01–S20 и границы их фактического покрытия приведены в отчёте `Артефакты_нейронки/ACCEPTANCE_PLAN5_2026-09-29.md`.
