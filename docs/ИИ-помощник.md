# ИИ-помощник в Beeline Business

## Назначение

Помощник — дополнительный чат для диспетчера, бригадира и выездного инженера. Он помогает получить сведения о рабочем дне из переданного backend контекста или найти инструкцию в базе знаний. Он не назначает исполнителей, не меняет маршрут и не заменяет рабочие операции приложения.

## Откуда берутся ответы

Вопросы о конкретных сменах, заявках, статусах и изменениях система старается разобрать как запросы к фактам. Ответ строится по контексту, который подготовил основной backend после проверки роли пользователя. Например, это может быть список назначенных работ или история изменений заявки. Если факта нет в переданном контексте, помощник не должен придумывать его.

Вопросы о порядке действий и правилах работ используют Markdown-базу знаний. Сервис ищет подходящие разделы с учётом роли и, когда возможно, категории открытой заявки. Найденные материалы и вопрос передаются языковой модели для формирования текста. Такой ответ является сгенерированным объяснением и требует проверки по действующему регламенту, особенно для вопросов безопасности.

Если вопрос не относится к доступному контексту или справке, полезного ответа может не быть. Генеративная модель способна ошибаться; чат не является источником нормативного решения.

## Роли и границы доступа

Пользовательский JWT проверяет основной backend. Он выбирает допустимую роль и подготавливает контекст, после чего вызывает внутренний API помощника. Сам сервис помощника не подключается к PostgreSQL и не авторизует пользователя самостоятельно; его endpoint рассчитан на вызов из доверенного backend-контура.

В API используются роли worker (исполнитель), foreman (бригадир) и observer (диспетчер). Доступные сведения ограничивает backend до вызова модели. Не передавайте помощнику больше данных, чем необходимо для ответа.

## Архитектура

    Пользователь → Backend: проверка доступа и сбор контекста
                         │
                         ▼
                   Assistant API
                    ├─ разбор фактов из контекста
                    └─ поиск в базе знаний → Ollama → сформулированный ответ

Assistant реализован как отдельный stateless-сервис FastAPI. Он получает сообщение, роль и контекст вместе с запросом, поэтому не хранит историю чата между вызовами. Для ответов по базе знаний используется retrieval с ранжированием разделов; модель формулирует ответ на основании переданных материалов.

## Модель и эксплуатация

В стандартной конфигурации используется Ollama и модель, выбранная параметром ASSISTANT_MODEL; шаблон проекта указывает qwen3.5:2b. В папке проекта есть отдельный процесс подготовки LoRA-адаптера и сборки GGUF-модели Beeline. Полученный файл не входит в репозиторий из-за размера и должен быть предоставлен отдельно. Поэтому наличие обучающего процесса не означает, что дообученная модель установлена в каждом запуске.

Модельные ответы требуют работающего Ollama и загруженной модели. При их недоступности ответы, собранные напрямую из фактов, могут продолжать работать, а генеративный ответ может завершиться ошибкой доступности.

## Данные и приватность

Основной backend определяет, какие сведения разрешено передать. Assistant API stateless, однако фактическая конфиденциальность зависит также от настроек логирования, сети и размещения Ollama. Локальный запуск модели сам по себе не доказывает, что данные нигде не сохраняются: это следует оценивать по конфигурации среды.

Для персональных и клиентских сведений используйте только одобренную конфигурацию проекта. Не помещайте реальные данные в публичные prompts, открытые issue или обучающие материалы.

## Как оценивать ответы

- Фактический ответ должен опираться на переданный контекст и быть сверяемым с данными системы.
- Ответ по инструкции должен быть связан с найденным разделом базы знаний.
- При отсутствии данных помощник должен обозначить границу знания.
- Генеративные ответы не следует использовать как автоматическое подтверждение безопасности, SLA или допустимости изменения плана.
- Все изменения заявок и маршрутов выполняются отдельными бизнес-операциями backend, а не чатом.
