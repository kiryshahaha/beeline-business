# API и интеграции

## Как проходит запрос

Backend предоставляет REST API для пользовательского интерфейса и внутренних интеграций. Аутентификация, роли, доступ к данным, предметные ограничения и транзакционное сохранение принадлежат backend. Полный интерактивный контракт OpenAPI доступен на /docs запущенного backend.

Основной цикл планирования:

1. Backend читает состояние заявок, смен, навыков, транспорта и оборудования для выбранного дня.
2. По координатам backend запрашивает у Geoapify дорожные матрицы и геометрию.
3. Backend отправляет расчётную задачу во внутренний planner через POST /api/v1/solve.
4. Planner возвращает порядок посещений, времена, статус поиска и метрики.
5. Backend перепроверяет ограничения; затем отдаёт preview или сохраняет его по команде apply.

Planner не получает пользовательский токен и не может читать или изменять базу. Ключ Geoapify остаётся на сервере. Ошибка внешней маршрутизации должна приводить к диагностируемому отказу или невозможности маршрута, а не к выдуманному road result.

## Основные группы операций

- Заявки: чтение, создание, изменение состояния, назначение и рабочий процесс.
- Планирование: preview, чтение сохранённого предложения, apply, текущая ревизия дня и пересчёт оставшегося маршрута.
- Маршруты: чтение сохранённой геометрии и истории.
- Импорт/экспорт: пакетный обмен CSV/XLSX и проверка данных.
- Аналитика и уведомления: операционные показатели и публикация событий.
- Дополнительные сервисы: Assistant API и push через Firebase, если интеграции настроены.

Эти группы являются функциональным обзором, а не исчерпывающим списком путей и схем запросов. Для точных параметров используйте OpenAPI конкретной версии backend.

## Сохранение планов

Preview не переписывает текущие назначения или маршруты. Он привязан к снимку данных и базовой ревизии. Apply сверяет актуальность, проверяет ограничения повторно и одной транзакцией сохраняет назначение, время, маршрут, уведомления и новую ревизию. Повтор запроса apply идемпотентен. Исторические ревизии не редактируются новым расчётом.

## Геоданные и карта

Geoapify предоставляет дорожные оценки и сегменты геометрии. Он не выбирает бригаду и не знает бизнес-приоритетов. MapLibre отображает карту; ключ картографической подложки относится к настройкам frontend, а не к серверному секрету Geoapify.

Без действующего ключа и доступности Geoapify нельзя считать дорожные данные проверенными живым источником. Применение резервного или тестового ответа должно быть явно отделено от оценки внешней интеграции.

## Необязательные сервисы

Assistant/Ollama обслуживает вопросы по переданному контексту и базе знаний. Он не выполняет запись назначений и не заменяет planner. Firebase может доставлять push-уведомления, если административная конфигурация включена; основной API и история заявок не должны зависеть от наличия Firebase.

## Импорт и безопасность

CSV/XLSX проходит проверку структуры, значений и ссылочной целостности перед изменением данных. Экспорт не является физическим дампом БД. Секреты, JWT и ключи внешних API задаются конфигурацией среды и не должны включаться в примеры документов или фикстуры.
