# Beeline Business

Beeline Business помогает выездной инженерной службе планировать и выполнять работы в рамках одного цифрового процесса. Диспетчер управляет распределением и проверяет план. Инженер получает отдельный мобильный экран со своим днём, маршрутом и заявками. Чат-помощник помогает команде освоить систему и инструкции.

Для расчёта система учитывает навыки, смены, транспорт, оборудование, участок обслуживания, клиентские окна и дорожное время Geoapify. Planner на OR-Tools предлагает порядок визитов; backend проверяет его до публикации. Подтверждённый план сохраняется вместе с GeoJSON и историей ревизий.

**Наше преимущество:** мы связываем экспертные правила с двумя специализированными интерфейсами и помощью инженеру, а не останавливаемся на отдельном расчёте маршрута.

## Диспетчер и инженер

Диспетчер видит карту и расписание команды, вручную назначает работы или запрашивает автоматический план, получает причины конфликтов и управляет изменениями. Инженер использует отдельный интерфейс «Мой день»: текущая и следующая работа, маршрут, карта, оборудование, карточки заявок и уведомления.

В приложении инженера есть ролевой чат. Он отвечает по разрешённым сведениям рабочего дня и помогает находить инструкции новой системы. Чат объясняет и поддерживает обучение, но не изменяет расписание и назначения.

## Как работает планирование

Backend читает согласованный снимок заявок и доступности, получает дорожные оценки, отправляет расчёт существующему solver и независимо проверяет ответ. Диспетчер сначала видит preview: план ещё не изменён. При подтверждении apply атомарно сохраняет назначения, времена, маршруты и новую ревизию.

Обычная новая заявка ищет свободный интервал. Авария может перестроить оставшуюся часть дня после безопасного завершения текущего этапа инженера. Назначение между разными участками обслуживания запрещено; города внутри одного участка сами по себе не ограничивают маршрут.

## Локальный запуск

Нужны Docker Desktop с Compose и локальные секреты окружения. Создайте .env из шаблона, задайте пароль PostgreSQL и секрет JWT, затем запустите основные сервисы:

    Copy-Item .env.docker.example .env
    docker compose up --build -d

Для планирования дополнительно задаются PLANNING_ENABLED, общий PLANNER_SERVICE_TOKEN и GEOAPIFY_API_KEY. Секреты среды не должны попадать в Git. После запуска веб-интерфейс доступен через единую точку входа на http://localhost (или http://localhost:3000 напрямую), документация backend API — на http://localhost/docs (или http://localhost:8000/docs).

## Честные границы

Качество маршрута зависит от корректных данных и доступности Geoapify. Поиск OR-Tools ограничен по времени и является эвристическим: FEASIBLE означает найденный допустимый план, но не доказательство глобального оптимума. Эффект для времени диспетчеризации, SLA и адаптации инженеров необходимо измерять на пилоте.
