# Структура frontend

Frontend разделяет код по пользовательским маршрутам, переиспользуемым интерфейсным компонентам и запросам к backend.

## Пользовательские маршруты

- app/page.jsx — диспетчерская карта и оперативный обзор.
- app/dispatch/ — распределение заявок по исполнителям и временной шкале.
- app/dashboard/ — аналитика, нагрузка и отчёты.
- app/worker/ — отдельный интерфейс инженера: «Мой день», маршрут, оборудование, карточки заявок, профиль и чат.
- app/login/ — вход в систему.
- app/settings/ — пользовательские настройки.

Ролевая маршрутизация направляет worker в приложение инженера, а остальные рабочие роли — в диспетчерский контур. Backend всё равно повторно проверяет права на каждой операции.

## Основные слои

- components/ содержит карту, панели диспетчеризации, рабочие карточки, формы и элементы интерфейса инженера.
- hooks/ загружает и обновляет серверное состояние через API.
- lib/ содержит API-клиенты, общие преобразования и функции мобильного контура.
- providers/ управляет сессией, ролями, темой и состоянием запросов.
- utils/ содержит форматирование данных и подготовку географических объектов.

## Связь с преимуществами продукта

Разделение маршрутов соответствует разным ежедневным задачам: диспетчеру нужны общая картина команды и управление распределением, инженеру — личная последовательность работ и контекст текущей заявки. Чат расположен в интерфейсе инженера, чтобы помощь по новым процедурам была рядом с рабочими действиями, а не в отдельном руководстве.

Для запуска и проверки frontend используйте инструкции в корневой справке каталога frontend.
